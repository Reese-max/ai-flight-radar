# 後續工作與驗收標準

## 本次交付範圍

價格快照、相同查詢比較、日權重統計、歷史證據門檻、取消品牌推定行李、未知時間不送分、通知成功才記錄、每任務租約、有限批次結束、錯誤延遲重試、過期報價排除、環境設定、測試與 CI 定義。

此清單描述程式碼範圍；不代表已在使用者電腦啟動服務，也不代表完成真實機票／通知／Docker 的端到端驗收。

## 下一階段優先順序

| 優先度 | 工作 | 驗收標準 |
|---|---|---|
| P0 | 真實報價取樣與來源健康 | 授權的小量線上查詢與訂票頁人工比對，記錄來源成功率、最後成功時間；不把mock測試當線上驗證 |
| P0 | 前端安全與天數一致性 | 不可信欄位只能以安全文字方式渲染；夜數與含首尾天數分開；未知價格/時間顯示未知 |
| P0 | NLP 範圍與排除詞 | 日本但不要北海道、指定城市與國家並列、下個月自然月、兩千元預算及不合理日期均有測試；不能只靠關鍵字誤解需求 |
| P1 | 任務租約續期及全域預算 | 長工作有 heartbeat；總體每來源並行、每分鐘與每日預算受控；多worker壓測沒有重複任務或暴衝 |
| P1 | 各通知渠道獨立 outbox | Telegram成功而ntfy失敗時，只重試失敗渠道；冪等鍵與送達狀態可查 |
| P1 | 依賴完整鎖檔及供應鏈 | 產生可重建的 lock/hashes；CI actions 固定審核過的 commit；定期更新與漏洞檢查 |
| P1 | 前端 E2E／Docker | 在實際瀏覽器測試 API相容、空資料及錯誤；映像可建置、非root啟動、資料持久化 |
| P2 | 第二獨立票源 | 來源真的不同、授權與計費明確，Provider registry 有超時、資料格式與故障降級測試 |
| P2 | 完整往返與含行李總價 | 逐航段身分、fare basis、幣別、旅客組合、行李、稅費及offer到期資訊可追溯；下單前重新確認 |
| P2 | 多使用者正式服務 | 身分驗證、資料隔離、通知私密性、速率限制、備份復原與稽核完成後才公開 |

不新增自動購票或付款。歷史資料不足不是透過生成虛構票價來解決；來源少也不是透過安裝多個同來源 MCP 來解決。
